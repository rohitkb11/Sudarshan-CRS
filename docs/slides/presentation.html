1. Introduction, Ideation & Brief Description

"Find the bug. Prove it's real. Fix it. Prove the fix holds. All without a human in the loop."

The Strategic Problem

Defence & national security software systems have millions of lines of code with zero-day exposure. Manual triage and verification cannot scale to modern cyber operational tempo.

The Solution

An autonomous Cyber-Reasoning System built on DARPA AIxCC top architecture (Buttercup), replacing unconstrained LLM wrappers with deterministic tools and ultra-fast targeted reasoning.

SLIDE 2 / 5

2. Detailed Methodology: The 7-Stage Pipeline

Stage 1: Intake & Build Harness

Disposable container builds Normal, ASan+UBSan, and libFuzzer binaries.

Stage 2: Discovery Engine

Semgrep static analysis generates smart seeds for bounded libFuzzer campaigns.

Stage 3: AST Context Map

Tree/regex indexing extracts only the buggy function slice, saving 90%+ tokens.

Stage 4: PoV Confirmation

Deterministic replay under sanitizers establishes indisputable proof.

Stage 5: Tiered Patch Gen

Rule Registry (Instant) → Patch Memory (CBR) → Groq Qwen/Llama Fallback.

Stage 6: Verification (V1–V4)

Rebuild → Replay → Regression → Differential Re-fuzz with 3-attempt feedback.

4. Salient Features & Novelty / USP

1. §8 Definition of Proof (V1–V4)

Includes Differential Re-fuzzing (V4) to prevent shallow patches that merely hide crashes (~40% flaw in baseline systems).

2. Patch Memory (Case-Based Reasoning)

Learns and caches verified remediation patterns. Grows faster and cheaper with every scanned vulnerability.

3. Dual Scan: Full vs Delta Scan

Enables instant CI/CD Pull Request auditing by concentrating fuzzing and analysis exclusively on incoming diffs.

4. Laptop & Edge Deployable

Requires no GPU clusters; runs inside lightweight disposable containers on single-laptop hardware (8 cores, 16GB RAM).
